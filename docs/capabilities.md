# Реестр возможностей: операции памяти и структурной навигации

Человекочитаемый реестр по **операциям** (не по именам инструментов): что за вопрос,
что за единица ответа, какие локальные затраты, где возможна модель/сеть, какие
побочные записи, какие допустимые repo/scope/ref-виды, какие бюджеты и какой fallback.
Это не автоматический роутер: документ описывает возможности, выбор остаётся за
агентом. Отличие от машинного manifest установки skills: manifest описывает файлы и
версии для установщика, здесь — стоимость и границы операций.

Заполнено только проверенное. Базис проверки: MegaMemory 2.5.1 (HEAD 36d4792, схема 14)
по коду `src/`, token-economy-ts 1.4.0 по `SKILL.md`, `scripts/graph-tool.js` и
`scripts/lib/refs.js`. Непроверенные системы не заполнялись; выдуманных batch, цен и
хранения здесь нет.

## MegaMemory — MCP-операции

| Операция | Тип вопроса → единица ответа | Локальная CPU/I/O | Модель/сеть | Побочные записи | Допустимые repo/scope/ref-виды | Бюджеты/batch/completeness | Fallback |
|---|---|---|---|---|---|---|---|
| `understand` (действие `query`) | «что граф знает о X» → карточки (`compact` по умолчанию, `full`, `brief` ≤8 строк) + `next` (`must_read`/`followups`/`record`), `refuted[]`, `meta` | FTS + векторный поиск по локальной БД; вектор запроса | Локальная модель эмбеддингов (первый запрос может загружать модель); сети нет | usage + timeline на каждый вызов | `file_refs` узлов — строки без валидации существования; git-опоры здесь не резолвятся | `top_k` 1–50 (деф. 10), `max_tokens` 100–20000 (деф. 1500); честная усечка: `meta.truncated`, `reason:"budget"`, `stale_excluded`/`inactive_excluded` | Структурный скилл и чтение файлов; без графа — обычная навигация |
| `get_concept` | «всё об узле id» → одна полная карточка: дети, рёбра, `informed_by`, trails, `support_check`, `current_digests` | БД + вычисление хешей support_check (без чтения файлов) | Нет | usage + timeline; в граф и снимки не пишет | Один id (алиасы разрешаются); опоры-файлы видны как узлы-якоря | Один id за вызов; `support_check` может быть `unknown`/`incomplete` — не «всё проверено» | `provenance_trace` для подграфа, `provenance_history` для версий снимков |
| `record` (форма записи: `create_concept`/`update_concept`/`link`/`remove_concept`) | «сохранить/исправить/связать/убрать знание» → узел/ребро/тумбстон + сообщение | БД; вектор при создании узла | Локальная модель эмбеддингов при создании; сети нет | nodes/edges/status_history; снимок только при явном `evidence.expect`; авто-дайджест родителя (5+ детьми); timeline | `evidence.ref` создаёт якорь: file, `HEAD\|sha:path` (git_blob), `git:tag\|commit\|branch:name` (git_ref); url не поддерживается | Дедуп по имени + косинусу (порог 0.92); заглушки без `allow_stub` отклоняются; эпистемические переходы валидируются; запись нового знания опциональна — чистое чтение не требует записи | `update_concept` вместо дубля; замена через `supersedes`; `remove_concept` — только когда знание действительно исчезло |
| `trail` (`trail_save`/`trail_get`/`trail_refresh`/`trail_extend`) | «цепочка рассуждения и её свежесть» → TrailView со state `fresh\|stale\|broken` и отпечатками участников | БД, отпечатки смысла | Нет | trail-таблицы; timeline | Узлы графа как участники цепочки | Отказ `refresh` на broken; refresh не оживляет refuted/abandoned/expired/удалённых участников | Проверка источников вручную; маршрут — данные, не исполняемый сценарий |
| `confirm_supports` | «зафиксируй версии, которые реально прочитал» → снимок опор решения | БД, сверка хешей claim/status/edge/artifacts | Нет | `support_baselines` + `support_revisions`; accepted_at на авто-рёбрах; timeline (write) | Node-опоры решения; `artifacts_digest` опционален | Любое расхождение — `version_conflict` без записи; пустой `items` = «опор нет» (легальный подтверждённый пустой набор); дайджесты берутся из ответов, не вычисляются вручную | Нет альтернативы: подтверждение выполняется только явным вызовом, автоматически не происходит |

Остальные MCP-инструменты (`list_roots`, `provenance_trace`/`provenance_audit`/`provenance_history`,
`check_artifacts`, slots/tasks/board) следуют тем же правилам: контракты описаны в
`tools/list`, README и коде; каждый вызов пишет timeline.

|---|---|---|---|---|---|---|---|
| `stats` | «состояние и активность графа» → счётчики, usage (окно 7 дней), `--funnel` | БД | Нет | usage-строки; `--prune` пишет ретеншн timeline; RW-открытие | — | `--funnel --json` без `--prune` — readonly-снимок; окно funnel не доказывает полноту (retention-лимиты) | `stats --funnel --json` для скриптов; `doctor` для здоровья |
| `doctor` | «здоров ли граф» → проверки + problems, exit 1 при проблемах | БД (RW-открытие, может мигрировать) | Нет | Возможная миграция при открытии | — | Информационные проверки не краснят; отсутствие записей не является проблемой | `stats` |
| `expire` | «поставить/заменить `valid_until`» → отчёт dry-run либо запись; `--scan` — обзор кандидатов | БД readonly (`--scan`/dry-run); `--apply` — атомарная запись | Нет | `--scan` никогда не пишет; без `--apply` — readonly; `--apply` пишет expiry выбранным узлам | `--scan`/`--json` — версионный отчёт кандидатов; применение — явно выбранные id (`--ids`) либо просмотренный отчёт (`--report`, строки с `expire: true` расставляет человек); `--scan --apply` запрещён | dry-run валидирует id и дату до записи; `--until past` — вчера; версионный отчёт (`format_version` 2) несёт время снимка, предложенную дату и версии полей — перед `--apply` весь набор сверяется в одной транзакции, расхождение даёт `version_conflict` на весь batch; старый формат применяется с явным предупреждением | Отказ с готовой командой на устаревшей схеме (readonly-пути); `scripts/report-journals.mjs` — текстовый adapter над тем же скан-модулем |
| `bench` | «дешевле ли граф чтения файлов/структурного инструмента» → ratios + `hit_rate` + quality-оси | БД + вызов `understand` на каждый вопрос + запуск внешнего TE-процесса | Сам граф — без сети; TE — произвольный внешний процесс по `--te-exec`/`--te-cmd` | usage на каждый вопрос + timeline | `--ref-root` для относительных file_refs, `--questions` JSONL | `--files-top 3` честнее «живого» baseline; `economy_status=not_measured` — полная экономия задачи не измеряется | `eval` для recall; `docs/bench-protocol.md` для протокола |
| `eval` | «находит ли поиск ожидаемые узлы» → recall@k + промахи | БД, гибридный поиск | Локальная модель эмбеддингов | Ничего (readonly) | `--file` JSONL пар `{query, expected_id, lang}` | `--k` (деф. 10), `--min` (деф. 0.8); fail-closed парсер с номером строки | `bench` для стоимости ориентации |
| `export` | «снимок графа в Markdown» → файлы в каталоге | БД readonly + запись файлов | Нет | Только файлы экспорта; база не меняется | Один файл на узел; путь выводится из имени узла | `--check` сравнивает с текущим рендером и exit 1 при расхождении; коллизии путей — ошибка; не архив истории (тумбстоны не переносятся) | Прямое чтение БД / `serve` |

## token-economy-ts 1.4.0 — операции структурной навигации

| Операция | Тип вопроса → единица ответа | Локальная CPU/I/O | Модель/сеть | Побочные записи | Допустимые repo/scope/ref-виды | Бюджеты/batch/completeness | Fallback |
|---|---|---|---|---|---|---|---|
| `search` (code-searcher.js) | «где встречается текст» → файлы, строки, короткие сниппеты (до 30 совпадений, строка ≤100 симв., дефолт) | Локальный обход исходников; каталоги зависимостей/сборок не обходятся | Нет | Нет (кроме кэша графа при последующих `graph`) | Корень проекта (`src`, если есть, иначе `.`); пути только внутри рабочей директории | `word=1`, `regex`, `ext`, `context=N`, `format=grouped/runs`; batch `requests=`/`requests_file=` — по-запросные результаты и ошибки; exit 0 при частичном провале (`failed>0`) | Встроенный поиск запрещён (строки >64 КБ ломают ripgrep); без скилла — чтение файлов |
| `outline` (symbol-index.js) | «скелет файла» → классы/функции/методы с номерами строк | Локальный парсер | Нет | Нет | Файлы `.ts/.tsx/.js/.jsx/.mjs/.cjs` внутри рабочей директории | До 60 строк символов (`limit=` меняет), `compact=1` с `L<start>-<end>`; batch; минифицированный код не предназначен для outline | `graph symbol` для отдельного объявления; чтение файла |
| `graph` (`info`/`symbol`/`deps`/`rdeps`/`path`/`component`) | «где определено / кто использует / как связаны» → JSON с файлами и строками | Локальный граф с кэшем; первый вызов строит граф, дальше инкрементально при изменениях | Нет | Кэш графа `graph-deps.json`/`.graph-deps-cache.json` — восстанавливаемый производный индекс, не источник знания | Рабочая директория; узлы по типу проекта (angular/react/nest/node/ts) | Batch читающих операций; неполный граф не доказывает отсутствия потребителей — `rdeps` перед правкой общего кода | Чтение файлов и поиск; кэш целиком не читать — только ответы операций |
| `graph op=read` | «точный текст диапазонов» → блоки строк с `startLine`/`endLine` | Чтение файла с диска | Нет | Нет | Один файл + `ranges` (1-based, включительно, слияние/сортировка); в 1.4.0 ещё additive `ref=` одним сырым локатором: `файл`, `файл:N`, `файл:N-M`, `файл#LN`, `файл#LN-LM` (bare `ref=файл` — полный текст только <300 строк и ≤1 МиБ, иначе `range_required` с точным путём и следующим шагом); git-виды (`git:tag\|commit\|branch:имя`, `HEAD:путь`/`sha:путь`) распознаются, но не читаются (`unsupported_ref_kind` — проверка git-опор остаётся в MegaMemory `check_artifacts`, без сети и без подмены working tree); путь только внутри рабочей директории (realpath-защита от symlink/junction) | Суммарный лимит 2000 строк за запрос — отказ, а не молчаливая усечка; диапазон за пределами/обратный/нулевой — ошибка; строка >64 КиБ по `ref=` — `line_too_long` без частичной выдачи; `ref=` одновременно с `file`/`ranges` — `conflicting_args`; в batch `ref=` у read-запроса (per-item error, `failed`, exit 0 ≠ полный успех); нормализованная выдача (BOM снят, EOL `\n`) — не исходные байты для artifact hash; в старых версиях (1.3.4) — fallback `file`+`ranges` с ручным разбиением локатора | Штатное чтение `Read(offset, limit)` |
| `sig` (sig-reader.js) | «сигнатуры сторонней библиотеки» → декларации классов/функций/членов из node_modules | Локальный резолв по package.json (exports/types) и реэкспортам | Нет | Кэш чтения файлов в рамках пакета | Bare-имя установленного пакета или путь внутри node_modules; realpath-защита | Обрезка сигнатур на 200 симв. с пометкой (`full=1` возвращает целиком, `offset` — хвост списков); batch; JSDoc/deprecated не переносятся | Не угадывать API без sig; чтение .d.ts целиком штатными инструментами запрещено правилами |
| `edit_symbol` (edit-symbol.js) | «заменить тело метода/функции» → правка файла | Чтение + запись файла | Нет | Правка целевого файла | Файлы внутри рабочей директории | Замена тела существующего объявления; целиком файл при правке <30% не перезаписывать | Штатный инструмент редактирования (замена фрагмента/diff) |
| `generate` (scaffold-helper.js) | «создать Angular-сущность» → новые файлы | Запись файлов | Нет | Создание файлов сущности | Рабочая директория проекта (angular) | Состав сущностей по правилам стека | Ручное создание по правилам скилла |

## Вне проверенного контракта

Hindsight и sgo-schedule — вне проверенного контракта, автоматически не вызывать. Их
код, настройки и хранение при составлении этого реестра не проверялись; возможности,
цены и хранение для них здесь не заполняются, интеграции с ними не строятся.

## Как проверять эти факты

- MegaMemory MCP: снимок `tools/list` и контрактные тесты ответов в `src/__tests__/`;
  readonly/письмо CLI — тесты `readonly-commands` и раздел README «Which commands never
  write to the database».
- token-economy-ts: локальные тесты скилла и правила `SKILL.md`; состав и хеш файлов —
  штатный manifest/`verify` skills.
- Экономия: `bench` измеряет стоимость ориентации (`economy_status=not_measured` для
  полной задачи); заявлять экономию можно только по протоколу whole-task.
