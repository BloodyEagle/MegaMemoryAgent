# Реестр возможностей: операции памяти и структурной навигации

Человекочитаемый реестр по **операциям** (не по именам инструментов): что за вопрос,
что за единица ответа, какие локальные затраты, где возможна модель/сеть, какие
побочные записи, какие допустимые repo/scope/ref-виды, какие бюджеты и какой fallback.
Это не автоматический роутер: документ описывает возможности, выбор остаётся за
агентом. Отличие от машинного manifest установки skills: manifest описывает файлы и
версии для установщика, здесь — стоимость и границы операций.

Заполнено только проверенное. Базис проверки: MegaMemory 2.6.1 (схема 14)
по коду `src/`, token-economy-ts 1.4.0 по `SKILL.md`, `scripts/graph-tool.js` и
`scripts/lib/refs.js`. Непроверенные системы не заполнялись; выдуманных batch, цен и
хранения здесь нет.

## MegaMemory — MCP-операции

| Операция | Тип вопроса → единица ответа | Локальная CPU/I/O | Модель/сеть | Побочные записи | Допустимые repo/scope/ref-виды | Бюджеты/batch/completeness | Fallback |
|---|---|---|---|---|---|---|---|
| `understand` (действие `query`) | «что граф знает о X» → карточки (`compact` по умолчанию, `full`, `brief` ≤8 строк) + `next` (`must_read`/`followups`/`record`), где `record` несёт форму опоры (`[{ref\|node, why}]` → `informed_by`), а не просто «запиши найденное»; при ≥3 завершённых чтениях с последнего зарегистрированного write — `next.unrecorded: {reads_since_write, last_write_at}` и однократное дополнение `record`: «С последней записи N чтений — если это законченный вывод, запиши его.»; поле и напоминание отсутствуют ниже 3, после write (включая удаление) и при `empty_base`; текущий вызов учитывается после ответа, чистое чтение не требует записи; `refuted[]`, `meta` | FTS + векторный поиск по локальной БД; вектор запроса; счётчик в памяти процесса, отдельно для пары БД/logger | Локальная модель эмбеддингов (первый запрос может загружать модель); сети нет | usage + timeline на каждый вызов | `file_refs` узлов — строки без валидации существования; git-опоры здесь не резолвятся | `top_k` 1–50 (деф. 10), `max_tokens` 100–20000 (деф. 1500); честная усечка: `meta.truncated`, `stale_excluded`/`inactive_excluded`; `meta.reason`: `empty_base` — нет живых (неудалённых) узлов, `no_match` — живые есть, но не прошли поиск/фильтры, `budget` — кандидаты не поместились; во всех трёх режимах первое поясняющее предложение и полный `next.record` обязательны и не обрезаются — если обязательный конверт не помещается, явная ошибка с просьбой увеличить бюджет; строка record в тексте brief имеет `RECORD_MAX = 400`, остальные строки — `LINE_MAX = 240`, полный `next.record` не обрезается; opt-in `include_evidence` (подтверждаемые версии всех живых опор в compact: `current_digests` + `support_evidence`, полные формулировки и rationale; матч размещается целиком или снимается — `meta.evidence_matches`/`evidence_supports`) и `collapse_ref_anchors` (свертка технических ref-якорей: вложение с rationale или collapsed-локаторы с зависимыми выводами, `meta.anchor_collapsed`; разрешение по id/пути и provenance не затронуты); reuse P1 (opt-in, только compact): `reuse: {task_type, files, negative?}` — квалификация паспортов по явному типу задачи и хешам области, секция `passport_reuse` (covered/gaps/qualification из 9 состояний; ни одно не повышает доверие молча, reusable — не покрытие кода; P4.1: кандидат с маршрутом несёт `route` с локаторами-статусами current/changed/missing/unchecked и пометками «данные, не команда» и «тесты — начальный набор проверок»; P4.2: у negative-паспортов reusable означает «не найдено в обследованной области» с манифестом, другой запрос/опции/новый файл дают query_mismatch/options_mismatch/new_file_in_scope и запрещают reuse); task-профиль P3 (opt-in, только compact): `task: {goal, kind, files?, context_epoch?}` — детерминированные обязательные категории источников по типу задачи, добор решений/тестов по явной области (score 0, скрытые зависимости), скрытые опоры размещённых решений, снятие смысловых повторов БЕЗ снятия refuted/противоречий/неполноты, uncovered со списком непокрытого и продолжением, оценочная ПОЛНАЯ цена (эвристика bytes/3, не токены провайдера); секция встраивается в этот же ответ, не подменяет `must_read`, `next.skip` пуст, покрытие кода не утверждается; `context_epoch` — явное состояние клиента (in-memory per-process, отпечаток проекта в ключе), сворачивает только уже выданные немандаторные карточки (решения/refuted/expired — никогда) | Структурный скилл и чтение файлов; без графа — обычная навигация |
| `get_concept` | «всё об узле id» → одна полная карточка: дети, рёбра, `informed_by`, trails, `support_check`, `current_digests`; профили: `orientation` (идентичность + квалификация + указатели), `evidence` (полные формулировки опор + rationale + готовые дайджесты `confirm_supports`), `full` (прежняя карточка) | БД + вычисление хешей support_check/дайджестов (без чтения файлов) | Нет | usage + timeline; в граф и снимки не пишет | Один id (алиасы разрешаются) или пакет `ids` ≤25 с одним общим бюджетом; опоры-файлы видны как узлы-якоря | `max_tokens` — финальный wire-бюджет сериализованного MCP-ответа (`tokens_estimated` — оценка estimator'а, не гарантия провайдерских токенов): fit включает ВСЕ метаданные (`returned`/`dropped`/`incomplete`, continuation и delta version/epoch); после сокращения выдачи счётчики и offset продолжения пересчитываются; если обязательный ответ не помещается, явный отказ с `meta.reason:"budget"`, а не oversized success; раскрытие соседей с капом (`max_neighbors`) + `continuation`, фиксирующий версию выборки (расхождение — `version_conflict`, повторить чтение); пакет: per-id статус/ошибка/неполнота, `budget_skipped` поимённо; batch-токен из `meta.continuation` передаётся как `{continuation: token}` без `id` и `ids` и маршрутизируется в пакетное продолжение (не одиночную карточку); кап вычислений support-check на пакет (10) с явным `support_check_deferred`; `support_check` может быть `unknown`/`incomplete` — не «всё проверено»; непоместившиеся формулировки — явная неполнота, не обрезка; delta E4 (opt-in, только одиночное чтение, не batch/continuation): `context_epoch` (≤256 символов) + `known_versions` — версия ЗАПРОШЕННОЙ проекции (состав+состояния+соседи+артефакты+формат, sha256 канонического JSON, stateless без кэша); совпадение — компактный `unchanged` с квалификацией-минимумом (не покрытие кода), расхождение/нет известных версий — полная выдача запрошенного профиля в его бюджете; после compaction/перезапуска/смены проекта клиент обязан сменить `context_epoch` И сбросить `known_versions` (либо не передавать оба параметра): новая эпоха сама по себе не отменяет старые версии у stateless-сервера | `provenance_trace` для подграфа, `provenance_history` для версий снимков; старый одиночный вызов без новых параметров — прежний ответ |
| `record` (форма записи: `create_concept`/`update_concept`/`link`/`remove_concept`) | «сохранить/исправить/связать/убрать знание» → узел/ребро/тумбстон + сообщение | БД; вектор при создании узла | Локальная модель эмбеддингов при создании; сети нет | nodes/edges/status_history; снимок только при явном `evidence.expect`; авто-дайджест родителя (5+ детьми); timeline | `evidence.ref` создаёт якорь: file, `HEAD\|sha:path` (git_blob), `git:tag\|commit\|branch:name` (git_ref); url не поддерживается | Дедуп по имени + косинусу (порог 0.92); заглушки без `allow_stub` отклоняются; эпистемические переходы валидируются; запись нового знания опциональна — чистое чтение не требует записи | `update_concept` вместо дубля; замена через `supersedes`; `remove_concept` — только когда знание действительно исчезло |
| `trail` (`trail_save`/`trail_get`/`trail_refresh`/`trail_extend`) | «цепочка рассуждения и её свежесть» → TrailView со state `fresh\|stale\|broken` и отпечатками участников; `trail_save` с opt-in `passport` — версионный паспорт разбора (тип задачи, цель, хеши целых файлов области, repo-идентичность, проверки, полнота, срок), `trail_get include_passport` возвращает тело или явный null. P4.1: необязательный `passport.route` — маршрут повторяющейся задачи (точка входа → инварианты → локаторы → проверочные действия, отвергнутые подходы с причинами, платформенные ограничения с воспроизведением); команды/локаторы маршрута — данные для проверки, не исполняемая команда; в reuse-выдаче локаторы получают статусы current/changed/missing/unchecked по тем же хешам области (номер строки — не идентичность). P4.2: необязательный `passport.negative` (только `task_type='negative_search'`) — ограниченный отрицательный результат: точный запрос + инструмент/режим + опции + те же хеши области; усечение/ошибка записи запрещены, дубликаты отклоняются (`negative.force_duplicate` — повторная проверка) | БД, отпечатки смысла; при паспорте — хеширование области (≤50 файлов) и git rev-parse HEAD | Нет | trail-таблицы; тело паспорта — в params существующего события `trail_save` timeline (легальная структура без DDL, подвержена ретеншну) | Узлы графа как участники цепочки; область паспорта — файлы/refs от repo_root | Хешируются целые файлы (консервативно); после вытеснения тела — честный `unknown` (trail_only), поиск по типу задачи без тела невозможен | Отказ `refresh` на broken; refresh не оживляет refuted/abandoned/expired/удалённых участников; reuse — understand.reuse, не trail |
| `check_freshness` | «какие выводы/паспорта затронуло изменение источника» → отчёт адресной перепроверки: `sources` (unchanged/changed/missing/unobserved/unstable/skipped/other_repo с текущими дайджестами), `records` (fresh/stale_input/partial/unknown с причинами), `dependencies` (static import-граф изменённых источников через adapter), `symbols` (разрешение определений через adapter: unique/ambiguous/missing — неоднозначное требует чтения), `summary` (affected/checked/unknown/truncated + limitations) и `expected_versions` | Чтение файлов/git-blob + SHA-256 содержимого, git-ref — SHA коммита (в `expected_versions[].sha256`); локальный git (status/rev-parse, аргументы массивом); при adapter — spawn node с таймаутом и изоляцией cwd | Нет (adapter — внешний локальный процесс по явной конфиг-точке `adapter.graph_tool`/env `MEGAMEMORY_CODE_ADAPTER`) | Не пишет знания, observations или подтверждения и не меняет граф; может записать/перестроить производный кэш `freshness-index.json`; обработчик MCP пишет служебный журнал вызовов (timeline и opt-in локальную телеметрию) | Файлы/git-объекты, цитируемые узлами/паспортами; repo_root — startup `--repo` или явный параметр; закрепления наблюдений не переписываются (расхождение пина — `other_repo`) | `max_files` (деф. 50, лишние — `skipped` + `truncated`), `max_deps` (деф. 20); один физический источник хешируется один раз за проверку; изменение источника в середине проверки — `unstable`, стабильный снимок не объявляется; проверенный префикс не выдаётся за весь граф (`unchecked_sources`/`partial`); mtime/size — не доказательство (SHA-256 для содержимого, SHA коммита для git-ref); статическая полнота символьного уровня — только объявленный scope adapter; ответ adapter на `op=rdeps` обязан нести `importedBy[]`, `importedByTotal`, `scope.scanRoot`, `completeness.complete` — без них/с неверными типами обход зависимостей даёт `adapter_error` (fail-closed, не «зависимостей нет») | Файловый режим без adapter (ЯВНО в отчёте); без adapter обход зависимостей недоступен — это НЕ «зависимостей нет» |
| `confirm_supports` | «зафиксируй версии, которые реально прочитал» → снимок опор решения | БД, сверка хешей claim/status/edge/artifacts | Нет | `support_baselines` + `support_revisions`; accepted_at на авто-рёбрах; timeline (write) | Node-опоры решения; `artifacts_digest` опционален | Любое расхождение — `version_conflict` без записи; пустой `items` = «опор нет» (легальный подтверждённый пустой набор); дайджесты берутся из ответов, не вычисляются вручную | Нет альтернативы: подтверждение выполняется только явным вызовом, автоматически не происходит |

Остальные MCP-инструменты (`list_roots`, `provenance_trace`/`provenance_audit`/`provenance_history`,
`check_artifacts`, slots/tasks/board) следуют тем же правилам: контракты описаны в
`tools/list`, README и коде; каждый вызов пишет timeline.

`next.record` — часть контракта ответа: kind выбирается по смыслу, `evidence` создаёт `informed_by`, а `file_refs` само по себе связей не создаёт.
Статические формы `record` ограничены `brief.LINE_MAX = 240`: иначе brief обрежет строку; динамическая причина refuted сохраняется дословно и может удлинить её.

## Вне проверенного контракта

Hindsight и sgo-schedule — вне проверенного контракта, автоматически не вызывать. Их
код, настройки и хранение при составлении этого реестра не проверялись; возможности,
цены и хранение для них здесь не заполняются, интеграции с ними не строятся.

## Как проверять эти факты

- MegaMemory MCP: снимок `tools/list` и контрактные тесты ответов в `src/__tests__/`;
  readonly/письмо CLI — тесты `readonly-commands` и раздел README «Which commands never
  write to the database».
- token-economy-ts: локальные тесты скилла и правила `SKILL.md`; состав и хеш файлов —
  штатный manifest/`verify` skills.
- Экономия: `bench` измеряет стоимость ориентации (`economy_status=not_measured` для
  полной задачи); заявлять экономию можно только по протоколу whole-task.
