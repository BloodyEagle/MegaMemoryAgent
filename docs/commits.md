# Коммит и PR

В сообщении коммита и описании PR укажите одну и ту же строку:
`memory: <id>` или `memory: нечего — <причина>`. Вместо `<id>` перечислите
реальные ID узлов, созданных или уточнённых по итогам работы.

## Шаблон коммита

```text
<type>: <краткое изменение>

memory: <id>
```

## Шаблон PR

```text
## Изменения
<что изменено и почему>

## Проверки
<выполненные проверки и ограничения>

memory: <id>
```

Если нового проверенного знания нет, замените строку `memory: <id>` в обоих
шаблонах на `memory: нечего — <причина>`, например:

```text
memory: нечего — чистое чтение и успешное переиспользование без нового знания
```

Это законный исход, а не повод создавать фиктивный узел. Записывайте только новое
проверенное знание, исправление существующего узла или нужную историю; существующий
узел уточняйте через `update_concept`, не создавайте дубль ради строки в коммите.

Шаблоны копирует и устанавливает владелец вручную. `megamemory guide` печатает
правило, но не создаёт коммиты, PR, записи памяти или шаблоны в других репозиториях.
Необязательный `megamemory hooks install [--repo PATH]` проверяет только наличие
строки `memory:` в сообщении коммита с кодом, не PR и не подлинность ID в БД;
`git commit --no-verify` и ранний выход чужого хука могут обойти проверку.
